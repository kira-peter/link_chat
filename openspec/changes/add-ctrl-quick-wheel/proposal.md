# Proposal

## Why

窗口底部的快捷键提示（`Tab switch pane  Alt+N channel  Alt+O dm  Alt+S settings  Alt+H help`）越加越长，页面一多就放不下，而且每个页面能做的事不同，固定一行提示要么不全，要么不对。改成「按一个键打开当前页面的快捷转盘」：一个入口覆盖所有页面，转盘里只列当前能做的事，底部提示只需一句话。呼出键可以在设置里选，避开输入法等冲突。

## What Changes

- **新能力 `tui-quick-wheel`**：在任何主界面页面按呼出键（默认 `Ctrl+Space`），从当前焦点处选中的条目辐射出一把「扇子」，列出对这个条目能做的事，后面接页面通用的操作，可做的操作全部显示。
  - 扇面朝条目周围空间大的方向展开，张角随操作数变化；选中项始终在正中，加框高亮，两侧渐淡，上下方向键循环转动。
  - 扇形之外的屏幕虚化，选中条目原样保留。
  - `Enter` 执行选中项，转盘关闭；再按一次呼出键或 `Esc` 关闭，不执行任何操作。
  - 动画：背景约 100ms 淡下、扇面淡入、选中项光带；转动立即到位。`Alt+M` 关闭动画时一律无动画。
- **底部提示**：状态栏的快捷键提示改为只显示「<呼出键> 打开快捷转盘」。
- **呼出键可设置**：设置 → 外观新增「快捷转盘按键」，候选为 `Ctrl+Space`（默认）、`Ctrl+G`、`Ctrl+K`、`Ctrl+O`、`F1`；作为账号设置同步。打开、再按一次关闭都用这个键，`Esc` 关闭始终有效。
- 不支持单独按 `Ctrl`：终端库收不到单独的修饰键，不为此修改终端库。
- **设置页**：选择模式的候选改用同样的扇形与动画，页面原地不动；设置页上按呼出键等同 Enter。
- 现有的 `Alt+` 快捷键全部保留，转盘只是新增的发现入口，不取代它们。

## Capabilities

### New Capabilities
- `tui-quick-wheel`: 快捷转盘：跟着选中条目的操作清单、扇形样式与虚化、可设置的呼出键、开关与执行、动画。

### Modified Capabilities
- `tui-chat-client`: 「状态栏与连接状态」与「快捷键与可发现性」两条要求：状态栏不再列出快捷键，改为提示转盘；快捷键的可发现性由转盘承担。
- `tui-settings`: 「设置项及其取值」：外观分类新增「快捷转盘按键」；「选择模式」：候选改为从选项的值处伸出的扇形，页面保持原样。
- `chat-protocol`: 「设置对象的键与校验」：新增 `wheel_key`，并补上已实现的 `plaza`。

## Version

Major：`4.0.0` → `5.0.0`。本变更新增了 `tui-quick-wheel` 能力。

## Impact

- `pkg/protocol`：设置表新增 `wheel_key`。
- `pkg/app`：转盘状态、呼出键匹配、每个页面的操作清单、执行分派；设置页新增一项。
- `pkg/tui/views`：扇形转盘渲染与背景虚化；`chrome.go` 的底部提示。
- 光带复用列表选中项的实现。
- `pkg/i18n`：转盘标签与提示文案。
- `docs/client.md`、帮助页、`CHANGELOG.md`、`VERSION`。
- 服务端只多认一个设置键，协议结构不变。
