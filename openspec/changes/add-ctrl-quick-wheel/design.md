# Design

## Context

动机见 `proposal.md`。与本设计相关的现状：

- tcell 不上报单独按下的修饰键，也丢弃按键抬起，所以只用组合键或功能键做呼出键，不改终端库。
- 组合键 `Ctrl+Space`（`KeyNUL`）、`Ctrl+G`/`Ctrl+K`/`Ctrl+O`（`KeyCtrlG` 等）、`F1` 在常见终端里都能收到，应用里目前也没有用到。
- 应用侧：`App.handleKey` 统一处理按键；`renderPage` 按页面绘制；`anim` 包已有列表选中项的光带；`chrome.go` 的 `keyLegend` 生成底部提示；账号设置在 `protocol.SettingSpecs` 里集中定义并校验。
- 每个页面的操作都已有对应的函数（`openNewPage`、`openSettings`、`openMoments`、`showMeSubpage`、`switchMomentsTab` 等），转盘只需把它们组织成清单。

## Goals / Non-Goals

**Goals:**
- 一种开关交互、所有页面一致；呼出键可在设置里选。
- 转盘清单与执行逻辑集中在一处，新增页面时只需加一张表。

**Non-Goals:**
- 不支持单独按 Ctrl 或「按住修饰键」的交互，不改终端库。
- 不允许任意录入呼出键，只在固定候选里选。
- 不用鼠标点选转盘项；不让用户自定义转盘内容；不移除现有的 `Alt+` 快捷键。

## Decisions

### 1. 开关交互，呼出键可设置

**选择**：呼出键打开转盘；打开时再按一次、按 `Esc`、执行后、窗口失焦（`EventFocus`）都关闭。呼出键是账号设置 `wheel_key`，候选为 `ctrl_space`（默认）、`ctrl_g`、`ctrl_k`、`ctrl_o`、`f1`。

**理由**：用户确认统一用开关交互。固定候选是为了保证每一个都能在终端里收到且不和现有功能冲突：`Ctrl+C` 是退出、`Ctrl+W` 删词、`Ctrl+I` 在终端里就是 Tab、`Alt+Space` 在 Windows 上会打开系统菜单。

**匹配**：`wheelKeyMatches(ev)` 按设置比较：`ctrl_space` 接受 `KeyNUL` 或带 `ModCtrl` 的空格；`ctrl_g`/`ctrl_k`/`ctrl_o` 对应 `KeyCtrlG`/`KeyCtrlK`/`KeyCtrlO`；`f1` 对应 `KeyF1`。

### 2. 转盘打开时独占键盘

**选择**：`App.handleKey` 最先检查转盘：打开时所有按键都交给转盘，处理完即返回。转盘只认 `←→↑↓`、`Enter`、`Esc` 与呼出键，其余按键忽略。

**理由**：避免用户以为在转转盘，下面的列表却在跟着动；也避免误把字母打进输入框。

### 3. 清单：选中条目的操作 + 页面通用操作

`pkg/app/wheel.go` 定义 `wheelItem{Label i18n.T, Run func(*App, ctx), Show func(*App) bool}`。`wheelItems()` 先按焦点与页面找到选中的条目（会话行、入口、好友、申请、广场的人、动态、评论、「我」的菜单项、主页、输入框），给出针对它的操作；再接上页面通用操作，按 Label 去重，按 `Show` 过滤。执行全部复用现有函数。打开时取一次清单快照。可做的操作全部显示，不设上限。

**理由**：用户要求选项从选中的东西出发；把通用操作放在后面，空页面上转盘也不会是空的。

### 4. 圆心：从画好的屏幕上找选中条目

**选择**：转盘打开时，先照常画完整个界面，再在焦点所在区域里找背景是选中色（`SelectedBg`）的单元格，取它们的外接矩形当作选中条目；找不到时用焦点区域的中心，输入框焦点时用输入框。

**理由**：每个页面画选中项的方式不同（整行底色、按钮、动态块），逐页计算位置要在每个 view 里暴露坐标，改动大还容易漏。所有页面的选中项都用同一个选中底色，从屏幕上读回来最省事，也不会和真实画面对不上。

### 5. 扇形排布

- 扇面方向取条目四周空间最大、且放得下全部选项的一边；都放不下时用屏幕中间的竖排列表。
- 半径 `r = max(上方项数, 下方项数) + 1`。第 d 项（与选中项的循环距离）比选中项「往回收」`2·(r - √(r² - d²))` 列，乘 2 是因为终端单元格高宽约 2:1。
- **对齐**：向右展开时每项的左端落在弧上；向左展开时每项的右端落在弧上。只对齐靠近条目的那一端，长短不一的名称不会让弧变形。
- **竖直**：选中项在线的顶端居中；第 a 圈的选项离线 `4 + off(a) - off(1)` 列（`off(a) = 2·√(r² - (r-a)²)`，4 列即两个汉字），与选中项的长度无关，所以转动时扇形形状不变。会话里焦点在输入框时，圆心固定为输入框，线从底部竖直向上。连线在最低一圈下方留 3 行的竿，不穿过选项；条目偏到一侧时线先横走再竖起。
- **拐弯**：四个方向都放不下时，线先竖着离开条目 2 行再拐向左或右，从拐角横向展开。
- **选中项**：加粗的 `Warning`（黄色）显示完整名称，不加边框；名称不截断，所以转动时位置不会跳。其余项按圈数从亮到暗。
- **连线**：从条目伸到选中项前一格；条目因屏幕边缘被迫离开所在行时，线在旁边拐一个直角。点列按从条目出发的顺序保存，伸缩时取前缀。
- 不显示按键提示。

### 6. 虚化

画完界面后遍历每个单元格，把前景色和背景色向主题背景色混合（约 82%，只隐约可见），选中条目所在的矩形跳过；无彩色终端改为把前景设为淡色。混合比例随动画变化，见决策 7。

### 7. 动画

- **打开**（`views.fanFrameAt`）：连线 140ms 内按「从条目到选中项」的顺序逐格伸出；之后选项按离正中的圈数 k 依次亮起，每圈间隔 70ms（圈多时压缩，总延迟不超过 420ms），每项 110ms 内亮到 `1 - 0.7·k/max(圈数,3)`，间隔大于单项亮起时间的一半，所以外圈明显晚于内圈出现；背景虚化在整个打开过程中逐渐加深。
- **关闭**：所有选项同时按同一个量变暗（180ms），外侧本来暗，最先降到 0；接着连线 130ms 内反向缩回；最后背景 120ms 内恢复。关闭时 `closeWheel` 立即交还键盘，把当时的清单、选中项和圆心位置存为快照，渲染层用快照播放关闭动画，播完即丢弃。
- **光带**：选中项完全亮起后，标签复用列表的 `shimmerText`。
- **转动不做位移动画**：上一版的环形转动在终端里因为整格跳动显得不顺，这一版转动立即到位。
- 动画关闭或无彩色时，以上都不播放。

### 8. 设置页的选择模式

设置页在选择模式下照常绘制（选中项保持选中高亮，其他选项不隐藏不变暗），并通过 `SettingsDrawn` 报告选中项所在行、值的位置与预览框。`settings_fan.go` 以值为圆心画同一个 `FanWheel`，`Keep` 传入该行与预览框，所以虚化时它们保持原样，预览仍随候选即时重绘。打开记录开始时间；确认或放弃时存快照播放关闭动画。原来的竖排候选与「上下各隐藏三行」的规则删除，列表的预留行保留以免布局变化。

设置页上按呼出键转为 Enter（选择模式中转为 Esc），不打开快捷转盘。

### 9. 清单范围与二级菜单

- 应用级操作（主题、动画、语言、设置、帮助、退出）只挂在首页的入口行上；其余页面只列自己的操作与相关设置。
- 各页面清单：
  - 会话列表选中私聊：发消息、查看主页、删除好友、拉黑；频道：进入；另有发起私聊、新建频道、筛选。
  - 「好友」「发现」「我」入口：打开 + 应用级操作。
  - 会话：跳到最新（有新消息时）、返回列表、气泡宽度、密度、时间格式、消息边框、消息时间、四种消息颜色。
  - 好友页：好友→发消息、查看主页、删除、拉黑；被拉黑→解除拉黑；申请→同意、拒绝、查看主页；广场的人→查看主页；另有添加好友、切换页签、返回列表、「出现在广场」。
  - 发现页：动态→赞/取消赞、评论、删除（自己的）、作者主页；评论→回复、删除（有权限）；另有发动态、切换页签、我的主页、返回列表。
  - 主页：发消息或加好友、拉黑、编辑资料（自己的）、返回。
  - 「我」页：打开选中项、快捷转盘按键、记住登录、返回列表。
  - 帮助、关于：返回「我」。
- `wheelItem.Setting` 不为空时，该项是设置：标签后附当前值；Enter 打开 `wheelSub`。二级菜单从一级选中项的文字处展开（`FanWheel.Draw` 返回选中项位置），一级只画选中项与连线，二级用平缓的弧（`Shallow`）以免候选多时散得太开。
- 预览：`previewSetting` 把候选写进当前生效的设置但不保存配置、不上传（`App.previewing`）；二级菜单打开时不虚化，页面以候选原样重绘。Enter 先恢复原值再走正常的 `applySetting` + 上传，Esc/关闭转盘恢复原值。
- 颜色设置的候选用 `MessageColorValue` 着色，选中的颜色候选保留自己的颜色，以加粗加下划线表示选中。颜色候选扩充为 14 种。

### 10. 底部提示

`keyLegend` 在主界面只返回「<呼出键> 打开快捷转盘」（取设置中的呼出键），两侧的连接状态等不变。各页面右下角已有的页面内提示（如朋友圈的「l 赞 · c 评论」）保留，它们说的是页面内的字母键，不是全局快捷键。

## Risks / Trade-offs

- **个别终端或输入法占用某个呼出键**（例如部分中文输入法用 Ctrl+Space 切换中英文）→ 设置里可换键；`Alt+` 快捷键全部保留，转盘不可用时不影响任何功能。
- **小终端或操作很多** → 扇面放不下时改竖排列表。
- **从屏幕读回选中位置** → 依赖「选中项用 SelectedBg」这一约定；找不到时退回焦点区域中心，转盘仍然可用。

## Migration Plan

客户端变更为主；服务端只在设置校验表里多认一个键 `wheel_key`（以及补上已有的 `plaza`），旧客户端不受影响。
