# Proposal

## Why

服务端现在完全没有管理入口：看不到在线情况和统计，处理不了违规账号，忘了安全问题的用户只能靠运维手改 `users.json`。聊天记录本来就存在服务器上，运营者需要一个「上帝视角」：看清服务器状态和所有对话，处置账号，并把这些能力按需分给不同的人。

## What Changes

- 服务端在原端口的 `/admin/` 下提供一个浏览器管理后台，页面随服务端二进制发布，不需要另外部署。
- **权限位**：账号可以持有四种管理权限，任意组合：
  - 查看统计（`stats.view`）
  - 查看聊天（`chat.view`）
  - 处置用户（`users.moderate`）
  - 管理账号（`accounts.manage`）

  后台只显示持有权限对应的区域。没有任何权限的账号无法登录后台。
- **超级管理员**：只能用服务端命令行 `-create-admin <用户名>` 创建或提升。超级管理员持有全部权限，任何人都不能降低它的权限、封禁它或禁言它。
- **概览**：运行时长、连接数、在线用户、用户、频道、私聊和消息的总量、近 24 小时消息量、内存与协程数、最近的服务端日志。
- **聊天浏览**：列出全部频道和私聊，按会话向上翻看历史，新消息实时出现。支持按关键词、作者、会话、时间范围跨会话搜索。
- **用户处置**：用户列表与详情（会话来源、处分历史）、封禁、禁言、解除、重置密码、强制下线。封禁和禁言必须填写原因，时长可选：1 小时、1 天、7 天、30 天、自定义或永久。
  - 封禁：立即断开该用户的所有连接，作废其会话令牌，此后拒绝登录、恢复会话和找回密码。
  - 禁言：用户可以登录和阅读，但不能发消息、编辑消息或建频道。
  - 两者到期都自动失效，所有记录永久保留。
- **账号管理**：建号（不设安全问题），授予或收回权限。任何人都不能改自己的权限。只能授予自己持有的权限。只有超级管理员能授予「管理账号」权限。
- **审计日志**：记录以下管理操作，持有「管理账号」权限的人可以查看：
  - 后台登录
  - 查看某个会话的消息（私聊和频道都记）
  - 搜索（包括关键词）
  - 处置用户
  - 建号、改权限

  不在聊天客户端做任何提示。
- **后台会话与聊天会话分开**：登录后台不会顶掉同一账号的聊天会话，两种令牌也不能互相冒用。
- **聊天客户端**：
  - 登录或恢复会话时被拒，或在线时被封禁，登录界面显示封禁原因和解封时间。
  - 被禁言时输入区不可用，显示「禁言至 …」，解除后自动恢复。
  - 新增错误码 `account_banned`、`muted` 和事件 `account.banned`、`account.muted`、`account.unmuted`。

## Version

Major：`1.0.0` → `2.0.0`。本变更新增了 `admin-console` 和 `account-moderation` 两项能力。它在 `add-build-version` 之后实施，所以起点是 `1.0.0`。

## Capabilities

### New Capabilities
- `admin-console`：管理后台的访问与认证、权限位与超级管理员规则、各区域（概览、聊天浏览与搜索、用户、账号、审计）的可见性与行为，以及实时事件流。
- `account-moderation`：封禁与禁言的语义、时长与自动到期、处分历史、管理员重置密码与强制下线，以及管理操作的审计日志。

### Modified Capabilities
- `account-auth`：被封禁的账号不能登录、恢复会话或找回密码。管理员建的号没有安全问题，因此不能自助找回。
- `login-session`：单会话约束只针对聊天会话。后台会话不计入，也不会顶掉聊天会话。
- `message-delivery`：被禁言的用户发送或编辑消息会被拒绝。
- `chat-protocol`：新增 `account_banned`、`muted` 错误码和 `account.banned`、`account.muted`、`account.unmuted` 事件。
- `server-runtime`：新增命令行创建超级管理员（服务端运行时拒绝执行），新增保存最近日志的缓冲供后台读取，新增后台开关配置。
- `tui-chat-client`：被封禁和被禁言时的界面表现。

## Impact

- **服务端（`pkg/server`）**
  - 新增后台 HTTP 接口和 SSE 事件流，挂在现有 mux 上。
  - 新增内嵌的静态页面，使用 `go:embed`，纯 HTML/CSS/JS，没有前端构建链。
  - 新增处分逻辑与审计。
  - 在登录、恢复会话、找回密码、发消息、编辑消息、建频道处加检查。
  - 在发消息和上下线处加通知后台的钩子。
  - 新增日志环形缓冲。
  - 新增数据目录锁文件。
- **存储（`pkg/storage`）**
  - 用户增加权限字段和超级管理员标记。
  - 新增 `sanctions.json` 和 `audit.jsonl`。
  - 新增每会话消息计数和跨会话搜索的接口。
- **协议（`pkg/protocol`）**：新增两个错误码和三个事件。现有请求不变。
- **客户端（`pkg/app`、`pkg/i18n`）**：处理上述错误码和事件，补充中英文案。
- **依赖**：`golang.org/x/term`、`golang.org/x/sys` 由间接依赖改为直接依赖，分别用于命令行无回显读取密码和数据目录加锁，不引入新模块。
- **命令行**：服务端新增 `-create-admin` 和 `-reset-password`，两者都只能在停服后执行。
- **兼容性**
  - 旧客户端遇到 `account_banned` 时按一般登录失败显示。旧客户端收到不认识的事件会忽略。
  - 已有的 `users.json` 没有权限字段，读取时视为没有任何权限，不需要迁移。
- **隐私**：持有「查看聊天」权限的人可以读到所有私聊。这一点由审计日志约束，客户端不做提示，这是有意的选择。
