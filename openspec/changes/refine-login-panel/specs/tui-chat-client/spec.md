# Spec Delta

## MODIFIED Requirements

### Requirement: 登录面板结构

登录面板 MUST 由用户名输入、密码输入、登录按钮三部分组成，按钮下方 MUST 提供「忘记密码」与「立即注册」两个可点击的文字链接。用户名与密码 MUST 各占一行，标签与输入内容在同一行。所有可交互元素 MUST 可用键盘到达，且当前焦点 MUST 有明确视觉标识。

#### Scenario: 面板包含两个字段、一个按钮、两个链接
- **WHEN** 登录面板渲染完成
- **THEN** 自上而下依次可见用户名、密码、登录按钮、忘记密码链接、立即注册链接

#### Scenario: 字段标签与内容同一行
- **WHEN** 登录面板渲染完成
- **THEN** 用户名的标签与其输入内容在同一行，密码的标签与其输入内容在同一行，两行的输入内容起始列对齐

#### Scenario: Tab 在全部可交互元素间循环
- **WHEN** 用户反复按 Tab
- **THEN** 焦点依次经过用户名、密码、登录按钮、忘记密码、立即注册并回到用户名，任何时刻都恰好有一个元素处于焦点

#### Scenario: Enter 激活当前焦点
- **WHEN** 焦点在登录按钮上按 Enter
- **THEN** 提交登录；焦点在某个链接上按 Enter 时激活该链接

#### Scenario: 鼠标点击链接
- **WHEN** 终端支持鼠标事件且用户点击「立即注册」
- **THEN** 打开注册表单

#### Scenario: 链接的视觉表现
- **WHEN** 渲染「忘记密码」与「立即注册」
- **THEN** 二者以带下划线的文字呈现，与按钮在视觉上可区分

### Requirement: 登录与首启引导

客户端 SHALL 用一个自足的登录面板完成身份认证，并在失败时给出可操作的说明。服务器地址 MUST 来自客户端配置而非常驻的输入字段，默认指向本机。每个客户端实例 MUST 使用独立的凭据存储。存在已保存的会话时，客户端 MUST 仍然显示登录面板由用户确认，MUST NOT 在用户确认之前自行登录。

#### Scenario: 首次启动
- **WHEN** 客户端没有任何有效配置
- **THEN** 客户端打开登录面板，只要求用户名与密码，服务器地址取配置中的默认值

#### Scenario: 服务器地址来自配置
- **WHEN** 用户需要连接另一台服务器
- **THEN** 用户修改配置文件或用启动参数指定地址，登录面板本身不提供该字段

#### Scenario: 服务器不可达
- **WHEN** 配置中的服务器地址无法建立连接
- **THEN** 登录面板显示不可达提示与正在使用的地址，并保留已填的用户名供重试

#### Scenario: 登录失败
- **WHEN** 用户提交错误凭据
- **THEN** 客户端在面板内显示失败原因（凭据错误、被限流等），不清空用户名

#### Scenario: 令牌持久化
- **WHEN** 用户登录成功并退出客户端后再次启动
- **THEN** 客户端显示登录面板而不是直接进入主界面，用户确认后才使用已保存的令牌登录，无需重新输入密码

#### Scenario: 已保存的会话需要用户确认
- **WHEN** 存在已保存的会话且用户尚未在面板上确认
- **THEN** 客户端停留在登录面板，不进入主界面

#### Scenario: 启动本身不产生登录
- **WHEN** 客户端启动且存在已保存的会话，用户尚未做任何操作
- **THEN** 客户端不向服务器发起会话恢复请求，该账号在别处的会话不受影响

#### Scenario: 同机多实例互不干扰
- **WHEN** 同一台机器上以不同实例名启动两个客户端
- **THEN** 二者使用各自的凭据文件，可以登录不同账号，互不覆盖

#### Scenario: 默认实例
- **WHEN** 用户未指定实例名启动客户端
- **THEN** 客户端使用名为 `default` 的实例配置，多个未命名的客户端共享该实例

## ADDED Requirements

### Requirement: 已保存会话的登录面板

存在已保存会话时，登录面板 MUST 预填上次的账号、以「已记住登录」状态取代密码输入，并 MUST 让焦点默认落在登录按钮上，使用户无需输入即可通过一次确认登录。

#### Scenario: 预填账号并免输密码
- **WHEN** 存在已保存的会话且登录面板打开
- **THEN** 用户名为上次的账号，密码位置显示已记住登录的提示而不是空输入框，焦点在登录按钮上

#### Scenario: 一次回车完成登录
- **WHEN** 焦点在登录按钮上且用户按 Enter
- **THEN** 客户端使用已保存的令牌登录并进入主界面，无需输入任何字符

#### Scenario: 令牌已失效时回落到密码登录
- **WHEN** 使用已保存令牌登录时服务端表示令牌已过期、被吊销或已被其他登录取代
- **THEN** 面板清除已记住状态、显示失败原因、把焦点移到密码输入，用户输入密码后可以正常登录

#### Scenario: 修改用户名即放弃已保存会话
- **WHEN** 用户改动了预填的用户名
- **THEN** 面板不再使用已保存的令牌，密码位置恢复为普通输入框，登录按密码进行

#### Scenario: 开始输入密码即放弃已保存会话
- **WHEN** 用户将焦点移到密码并输入字符
- **THEN** 面板按普通密码登录处理，已保存的令牌不会被使用

#### Scenario: 关闭记住登录后不出现该状态
- **WHEN** 用户已在设置中关闭记住登录
- **THEN** 登录面板显示普通的空密码输入框，焦点在密码输入

### Requirement: 登录按钮外观

登录按钮 MUST 以带边框的紧凑方框呈现，宽度 MUST 由其文字内容决定而不是铺满整行。选中时 MUST 有一道光带自左向右扫过按钮文字，并受统一的动画开关控制。

#### Scenario: 按钮是带边框的紧凑方框
- **WHEN** 登录面板渲染完成
- **THEN** 登录按钮四周有边框，宽度只比其文字多出固定的内边距，居中显示，不延伸到面板两侧

#### Scenario: 选中态使用强调色
- **WHEN** 焦点在登录按钮上
- **THEN** 按钮的边框与文字以强调色显示，未选中时以弱化色显示

#### Scenario: 选中时光带扫过按钮文字
- **WHEN** 焦点在登录按钮上且动画开启
- **THEN** 一道光带自左向右扫过按钮上的文字，文字与边框的位置保持不变

#### Scenario: 未选中时没有动画
- **WHEN** 焦点不在登录按钮上
- **THEN** 按钮静止显示，不产生持续刷新

#### Scenario: 关闭动画后选中态为静态
- **WHEN** 用户已关闭动画
- **THEN** 选中的按钮以静态强调色显示，没有光带

#### Scenario: 单色终端仍可辨别选中
- **WHEN** 终端不支持有效的颜色差异
- **THEN** 选中的按钮仍可通过边框样式或移动的标记与未选中状态区分

### Requirement: 登录面板的紧凑版式

登录面板 MUST 以尽量少的行数承载其全部内容，不留多余的空行。字段标签 MUST 采用定宽列，使两个字段的输入起始位置对齐。

#### Scenario: 面板高度紧凑
- **WHEN** 登录面板渲染完成
- **THEN** 面板内容区的行数不超过各元素所需行数之和加固定的几个间隔行

#### Scenario: 不同语言下输入列对齐
- **WHEN** 界面语言在中文与英文之间切换
- **THEN** 两个字段的输入起始列仍然对齐，标签宽度按当前语言中较长者确定
