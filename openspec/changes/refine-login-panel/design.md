# Design

## Context

登录面板现状（`pkg/tui/views/dialogs.go` 的 `RenderLogin`）：

- 每个字段占两行（标签一行、输入一行），之间隔一个空行，共 7 行；面板高度 15。
- 登录按钮用 `TextFill` 铺满到字段宽度，选中时整行着 `Selected` 背景。
- 启动流程（`pkg/app/app.go`）：`New()` 里若 `a.st.Token != ""` 就**不打开**登录框，`Run()` 里随即 `connectToResume`，直接 resume 并进入主界面。

上一轮 `fix-session-liveness` 让 `auth.resume` 会顶掉该账号的其他会话。这样"启动即自动 resume"变成了一个**有副作用的动作**，但用户看不到它发生。

## Goals / Non-Goals

**Goals:**

- 版式更紧凑；按钮看起来像按钮；选中态有和输入框一致的"活"的感觉。
- 已保存的会话仍需用户确认一次，且确认动作最小（一次回车）。
- 令牌失效时能顺畅回落到密码登录，用户不会卡在一个"记住了但登不上"的状态里。

**Non-Goals:**

- 不改服务端协议。已保存会话仍是 `auth.resume`，只是触发时机从"启动"挪到"用户按下按钮"。
- 不做"多账号选择器"。只有一个已保存会话，要换账号就改用户名。
- 不为按钮光带另写一套动画引擎，复用 `anim.Shimmer`。

## Decisions

### 1. 已保存会话是登录面板的一种**状态**，而不是第三种登录方式

**选择**：`LoginModel` 增加 `Remembered bool`。为真时：

- 密码行显示「已记住登录」（弱化色）而不是输入框；
- `Focus` 初始为 `LoginFocusSubmit`；
- 按钮提交时走 `callResume`，否则走 `callLogin`。

**理由**：让它成为面板状态，意味着渲染、键位、提交三处都只需多一个分支，不需要新的对话框类型或新的启动界面。

**放弃已保存会话的条件**（任一发生就把 `Remembered` 置假，密码行变回普通输入）：

1. 用户名被修改——令牌属于特定账号，换名字就不该再用；
2. 用户在密码行输入任何字符——说明用户想用密码；
3. resume 失败（令牌失效）——自动回落并聚焦密码行。

这三条保证"已记住"状态永远只在它**确实有效且用户没有表示别的意愿**时存在。

### 2. 启动不再自动 resume

`Run()` 里去掉 `connectToResume`，`New()` 里无论有无令牌都打开登录面板。网络连接推迟到用户按下按钮时才建立（`connectForLogin` 路径已经存在）。

**这同时修了一个隐藏的问题**：之前打开客户端就会顶掉别处的会话，用户毫无察觉。现在顶号只发生在用户明确按下登录之后。

**替代方案**：保留自动 resume，只在面板上显示"正在登录…"并允许取消。放弃——自动执行带副作用的动作再让用户"取消"，比让用户"确认"更容易误伤。

### 3. 令牌失效的回落

resume 的失败码有三种值得区分：

| 服务端返回 | 含义 | 客户端处理 |
|---|---|---|
| `token_expired` | 过期 | 清令牌，回落密码登录 |
| `unauthorized` | 已被吊销或被别处顶掉 | 清令牌，回落密码登录 |
| 网络错误 | 服务器不可达 | **不清令牌**，保持已记住状态，显示不可达提示 |

最后一行很重要：服务器暂时连不上时不应该丢掉用户的已保存会话，否则一次断网就把"免输密码"永久丢了。

回落时：`Remembered=false`、`Err` 显示原因、`Focus=LoginFocusPassword`。

### 4. 单行字段的版式

```
┌─ 登录 ─────────────────────────────────────┐
│                                            │
│   用户名   alice█                          │
│   密码     ••••••                          │
│                                            │
│              ┌──────────┐                  │
│              │   登录   │                  │
│              └──────────┘                  │
│        忘记密码    立即注册                │
│   ws://127.0.0.1:8100/ws                   │
│   Tab 切换 · Enter 确认 · Esc 退出         │
└────────────────────────────────────────────┘
```

标签列宽取 `max(StringWidth(用户名), StringWidth(密码))` + 2 间距，两种语言各自计算——中文两个标签都是 3 个全角字符宽度不同（`用户名`=6 格、`密码`=4 格），英文 `Username`=8、`Password`=8，所以必须按当前语言取最大，不能写死。

输入区从标签列之后开始，到右边距结束。焦点字段用现有的 `Selected` 背景填充输入区部分（不含标签），仍然有 `█` 光标。

**高度**：2（上边距）+ 2 字段 + 1 间隔 + 3 按钮 + 1 链接 + 1 状态 + 1 提示 + 1 下边距 + 2 边框 ≈ 12 行，比原来的 15 行少 3 行。

### 4b. 已记住状态下的密码行

不画输入框，只画一行弱化色文字 `已记住登录 · 按 Enter 直接登录`，`•` 掩码不显示（那会暗示有 N 个字符，而实际上并不存在）。

### 5. 按钮方框与光带

按钮 3 行高（上边框、文字行、下边框），宽度 = 文字宽度 + 2×内边距 + 2 边框。用现有的 `Canvas.Box` 画边框。

选中时，文字行的每个单元格按 `anim.Shimmer.Brightness` 着色，边框用强调色。光带复用 `DefaultShimmer`，但按钮文字很短（`登录` 才 4 格宽），默认带宽 σ=2.6 会让整个文字同时亮起，看着像闪烁而不是扫过。

**解决**：按钮用单独的 `ButtonShimmer`，σ 缩到约 1.2，并把光带的行进范围扩展为"整个按钮内部宽度"（包含内边距），让光带穿过**空白内边距**再到文字，延长行进距离，视觉上才是"扫过"。

**时间基准**：从按钮获得焦点那一刻开始计时，复用 `shimmerStart` 的做法：`a.anim.buttonStart`，在焦点移到按钮时重置，保证光带总是从左边进入。

### 6. 动画刷新判定

`needsFrames` 增加一个条件：登录面板打开 && 焦点在登录按钮 && 动画开启。其余不变。这样登录面板在焦点不在按钮上时仍然是零刷新。

## Risks / Trade-offs

- **启动多一次确认** → 对已经习惯"打开即用"的用户是退步。缓解：只需一次回车，且焦点已经在按钮上。这是为了换取"顶号不再静默发生"，我认为值得。
- **已记住状态下用户可能不知道密码行为什么没有输入框** → 明确写出"已记住登录 · 按 Enter 直接登录"，并且一旦输入字符就恢复普通输入框，不会卡住用户。
- **服务器不可达时按钮看似没反应** → 提交后立即显示 `正在连接…`，失败后显示不可达原因并保留已记住状态，可重试。
- **按钮光带的 σ 要和输入框的区别开** → 用单独的参数而不是共享常量，避免以后调一处影响另一处。

## Open Questions

- 光带在按钮里的带宽（σ≈1.2）和速度是按文字宽度推算的，需要实际看一眼；参数集中在 `anim` 包的一处，容易调。
