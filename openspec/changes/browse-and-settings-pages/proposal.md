# Proposal

## Why

现在左侧列表要按 Enter 才会打开会话或入口，上下移动只是挪光标，右边不跟着变；「设置」「帮助」「关于」还是浮在界面上的弹窗，和聊天区是两套交互。用户希望列表「移到哪里、右边就显示哪里」，入口页面和聊天窗口用同一套左右结构和折叠方式。设置本身也只是一张平铺的长表，没有分组，改动外观类选项时看不到效果。

## What Changes

- **上下移动即选中**：焦点在列表时，光标移到哪一行，右侧就显示什么，不再需要 Enter：
  - 私聊、已加入的频道：右侧直接显示该会话的消息，视为打开（未读清零）。
  - 未加入的频道：右侧只显示**预览页**（频道名、简介、成员数、「按 → 或 Enter 加入」），**不会**发出加入请求，不会给频道里的人产生「加入了」的系统消息。
  - 设置、帮助、关于：右侧显示对应页面。
  - `→`（以及 `Enter`）仍然表示「把焦点交给右侧」，同时列表折叠、名字飞到正上方居中；对未加入的频道，这一步才真正加入。`←` 返回列表并展开，规则不变。
  - 快速连续移动时，历史消息的加载会合并，不会每扫过一行就请求一次。
- **入口改成页面**（**BREAKING**，仅界面行为）：设置、帮助、关于不再是弹窗，而是右侧的页面，和聊天窗口一样随焦点折叠与展开，页面标题和会话名一样飞到正上方居中。`Alt+S` / `Alt+H` 直接进入对应页面并把焦点交给它。退出登录的二次确认仍是弹窗。
- **设置改为分层结构**：
  - 左栏是**分类**，按块分组（参考常见聊天软件：「账户」「外观」「聊天」「通用」等），块之间有小标题和间隔。
  - 右栏是所选分类下的**选项**，每项显示当前值。
  - 层级之间用 `←` / `→` 来回切换：分类栏按 `→` 进入选项栏；选项上按 `→` 进入**选择模式**——可选值以竖排滚轮的样子显示，当前值在中间、高亮，上下的候选值颜色稍淡，`↑` `↓` 切换候选，`Enter` 或 `→` 确认，`←` 或 `Esc` 放弃。分类栏上按 `←` 离开设置、回到会话列表。
  - 只读项（服务器、用户名、凭据存储）不能进入选择模式；动作项（退出登录）进入的是确认。
- **微型预览**：会影响聊天界面的分类（外观、聊天）在选项下方显示一个小型的聊天预览，用真实的气泡渲染。选择模式中切换候选值时预览**立即**按候选值重绘，确认前就能看到效果，放弃则恢复。
- **新增聊天类设置**（均持久化，默认值与现在的表现一致）：
  - 气泡最大宽度：60% / 70% / 80%（默认 70%）。
  - 消息密度：舒适 / 紧凑（默认舒适；紧凑时不同发言人的分组之间不留空行）。
  - 时间格式：24 小时 / 12 小时（默认 24 小时）。
- **帮助、关于页面**：帮助按分组排版、可上下滚动；关于显示应用名、版本和简介。

## Capabilities

### New Capabilities
- `tui-settings`: 设置页的分层结构、分类分块、选择模式、微型预览，以及各项设置（含新增的聊天类设置）的取值与持久化。

### Modified Capabilities
- `tui-chat-client`: 会话列表的「移动即选中」与未加入频道的预览；左侧底部入口从「Enter 打开对话框」改为「选中即在右侧显示页面」；帮助与关于改为页面；快捷键帮助改为页面；区域方向语义与折叠过渡的对象从「会话」扩展为「右侧当前显示的内容」，且上下移动本身不折叠。（气泡宽度、密度、时间格式对消息区的影响写在 `tui-settings` 中。）
- `tui-design-system`: 边框的使用范围（设置不再是对话框，新增预览框）；选择模式中候选值逐级变淡的样式。

## Impact

- 代码：`pkg/app`（焦点与右侧内容的模型、列表移动、设置的状态机、配置字段、历史加载合并）、`pkg/tui/views`（设置页、帮助页、关于页、频道预览页、微型预览、消息布局参数化）、`pkg/i18n`（新文案）、`pkg/client`（右侧内容的选择）。
- 配置文件新增 `bubble_width`、`density`、`time_format` 三个字段；旧配置缺省即为当前行为，无需迁移。
- 服务端与协议不变：频道列表已经返回 `joined`，客户端据此决定预览还是直接显示。
- 文档：`docs/client.md` 的快捷键、列表、设置章节需要重写。
