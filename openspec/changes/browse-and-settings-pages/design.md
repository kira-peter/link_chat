# Design

## Context

见 proposal.md 的 Why。和实现方式相关的现状：

- **右侧现在只认一种东西：会话。** 折叠目标（`foldTarget`）、名字飞行（`nameFlight`）、焦点竖条位置（`regionX`）、右侧渲染（`renderTranscriptAndComposer`）都直接读 `ActiveID`。折叠的规则是「焦点在输入区且有打开的会话就折叠」。
- **设置、帮助、关于是 `ui.Dialog` 驱动的模态弹窗。** 弹窗打开时按键全部交给对应的 `handleXxxKey`，渲染在最上层。设置的行是一张由 `refreshSettingsRows` 拼出的平铺表，靠标签文字（`row.Label`）分派动作。
- **打开会话有副作用**：清未读、存/载草稿、`joinAndLoad` 对频道发 `channel.join`（服务端对首次加入广播「joined」系统消息），再拉一页历史。
- **频道列表包含所有公开频道**，每项带 `joined`。没加入的频道，服务端拒绝返回历史（`CodeForbidden`）。
- **消息布局常量是包级常量**：`bubbleMaxPercent = 70`、分组之间固定一个空行、时间由 `i18n.ClockOnly` 等固定 24 小时格式。

## Goals / Non-Goals

**Goals:**
- 右侧内容由一个统一的概念驱动，会话和三个入口页面共享折叠、飞行、竖条、标题居中这一整套机制，不再为每种页面复制一份。
- 上下移动只做「便宜、可撤销」的事：切换显示、清本地未读、按需拉一次历史；不产生对他人可见的副作用。
- 设置页的状态机（分类 → 选项 → 选择模式）是纯数据加纯函数，可以不起 App 直接测。
- 微型预览走与正式消息区完全相同的布局与绘制代码，只是参数不同，保证「预览里看到的就是之后看到的」。

**Non-Goals:**
- 不做鼠标拖拽、滚轮在选择模式中的操作（键盘优先；已有的点击行为不扩展）。
- 不新增主题，也不改主题令牌的取值。
- 不改协议和服务端。「未读」仍然是本地概念，不回传服务端。
- 窄屏（单栏）下的设置页只要求可用：分类、选项、选择模式依次占满一屏，不做双栏，不显示预览。

## Decisions

### 1. 右侧内容是一个「页面」，会话只是其中一种

新增 `ui.Page`（`PageConversation`、`PageChannelPreview`、`PageSettings`、`PageHelp`、`PageAbout`，以及无内容时的 `PageWelcome`）。列表光标的位置**唯一决定** Page：会话行 → 已加入或私聊为 `PageConversation`、未加入为 `PageChannelPreview`；入口行 → 对应页面。

- 折叠规则改为「焦点在右侧且 Page 不是 Welcome 就折叠」。`FocusInput` 改名为 `FocusRight` 的成本太大（测试与文档大量引用），所以保留 `FocusInput` 这个值表示「焦点在右侧」，由 Page 决定键交给谁：会话页交给输入框，设置页交给设置状态机，以此类推。
- 飞行与标题：每种 Page 提供自己的标题文字（会话名 / 「设置」/ 「帮助」/ 「关于」/ 频道名），`TitleAnchor`、`nameFlight`、`regionX` 改读 Page 的标题，不再只读 `Active()`。飞行起点是该 Page 对应的列表行（入口行同样有锚点）。
- **为什么不保留弹窗，只是换个位置画？** 弹窗的问题不是位置，而是它夺走全部按键、绕开焦点模型。做成 Page 后，`←` 回列表、`Alt+*` 全局键、焦点竖条、折叠全部自然成立，不需要为设置单独再写一遍。
- 退出登录的二次确认仍用 `DialogConfirm`：它确实是要打断一切的模态确认。

### 2. 上下移动即选中：分两步，显示立即、加载去抖

光标移动时同步做：设 Page、对会话设 `ActiveID`、存/载草稿、清本地未读、`syncMarker`。网络部分（`joinAndLoad` 中的拉历史）**不**立即发，而是在光标停留 150ms 后对最终停下的会话发一次；期间显示已有的本地消息，没有则显示「加载中」。

- 去抖用的是 App 已有的帧/定时机制：记录 `pendingLoad{id, at}`，在主循环的 tick 里检查到期。不用 `time.AfterFunc`，因为它的回调跑在别的 goroutine 上，需要额外加锁并且难以在冻结时钟的测试里控制。
- **未加入的频道**：光标经过只设 `PageChannelPreview`，不设 `ActiveID`、不 join、不拉历史。`→`/`Enter` 时才走现在的 `openConversation`（会 join）并把焦点交给输入框。所以「加入了」系统消息只在用户明确确认时出现。
- 已加入频道的 `channel.join` 是幂等、静默的（服务端已有此约定），但仍然不在光标移动时发，统一放进去抖后的加载里，避免扫过一排频道产生一排请求。
- **替代方案：光标移动只「预览」、Enter 才「打开」**（不清未读、不设 ActiveID）。被否：用户明确要求移动即选中，而且「看到了但未读还在」会让未读数失去意义。

### 3. 设置是一份声明式的目录

设置的结构写成一张静态表：`[]SettingsSection{Title, []SettingsCategory{ID, Title, Preview bool, []SettingsItem{ID, Kind(ReadOnly/Choice/Action), Choices func(*App) []Choice, Get, Set}}}`。分类块、选项、候选值、是否显示预览都从这张表来；渲染和按键处理只认这张表，不再按标签文字分派。

- 状态是 `SettingsNav{Level(Category/Item/Choose), Cat, Item, Choice, Original}`。按键 → 新状态是纯函数 `nav.Key(key, catalog)`，可单测；副作用（保存配置、切主题）只在「确认」那一步由 App 执行。
- 选择模式的「即时生效于预览」：预览渲染时用 `Choice` 指向的候选值覆盖对应设置，**不写入**真实配置；确认才 `Set` + `SaveConfig`；放弃直接丢掉 `Choice`。主题这一项特殊：预览要用候选主题的令牌渲染，所以预览框用 `theme.NewTokens(候选)` 单独构造令牌，主界面其余部分保持原主题，直到确认。
- 动画开关、语言在选择模式中**只影响预览**，确认后才全局生效——否则在候选之间上下移动就会让整个界面语言来回跳。
- 分类划分（左栏）：
  - 个人：账户（用户名、服务器、凭据存储、记住登录、退出登录）
  - 界面：外观（主题、动画）⟶ 有预览；聊天（气泡宽度、密度、时间格式）⟶ 有预览
  - 系统：通用（语言）

### 4. 消息布局参数化

`LayoutMessages` 增加一个 `Layout{BubblePercent int, Compact bool, Clock24 bool}` 参数，替换现在的包级常量。`TranscriptModel` 带上它，App 从配置构造。预览框调用同一个 `LayoutMessages` + `drawWindow`，传入候选值。

- 12 小时制格式化放进 `i18n`（`ClockIn(millis, clock24, lang)`），中文「下午 8:26」、英文「8:26 PM」，与现有的日期前缀规则组合。
- 紧凑密度只去掉「不同发言人分组之间」的空行；时间行上下的空行保留，因为它们是时间行可读性的一部分（spec 已写明）。

### 5. 选择模式的竖排滚轮

候选值以光标项为中心竖排，最多显示 5 行（上下各 2 个），超出部分不显示；选项栏里该项所在行就是中心行，上下候选覆盖在相邻的选项行之上（选择模式期间其他选项被暂时遮住），不推开布局。这样进入/退出选择模式时其他元素不跳动。

- 颜色：中心项用选中态；±1 用 `Muted`；±2 用 `Faint`。单色终端两侧加 `‹ ›` 标记。
- **替代方案：在选项下方展开一个下拉列表。** 被否：会把预览框往下推，导致预览在进入选择模式时跳动；用户描述的也正是「上下显示待选项」。

### 6. 帮助与关于

帮助页复用现有的 `HelpRows` 数据，按组排版成两列（键 / 说明），可以用 `↑` `↓`、`PgUp` `PgDn` 滚动；关于页是静态内容。两者都只有一层，`←` 直接回列表。

## Risks / Trade-offs

- **[风险] 光标扫过即清未读，用户可能「误读」。** 快速向下找某个会话时，路过的会话未读全被清零。→ 清未读与显示同步发生是用户要的语义；但为了减少误伤，清未读与加载一样放进 150ms 去抖：只有光标在该会话上停下才清零，快速扫过的不受影响。
- **[风险] 去抖引入时间相关的状态，测试容易不稳定。** → 使用已有的冻结时钟 `freezeClock`，去抖到期判断只依赖 `nowTime()`，在测试里推进时钟即可，不依赖真实等待。
- **[风险] 设置页从弹窗改为 Page，约 14 处测试依赖 `DialogSettings/Help/About`。** → 这些测试按新语义迁移，而不是保留旧枚举做兼容层；`DialogSettings` 等枚举值删除，编译器会指出所有遗漏。
- **[风险] 主题候选预览需要并存两套令牌。** → 只有预览框用候选令牌，且在单一渲染函数内局部构造，不碰 `a.tokens`；确认时才 `applyTheme`。
- **[取舍] 未加入频道的预览没有消息内容。** 服务端不给未加入者看历史，预览只能展示名称、简介、成员数、最后活动时间。这是有意的，与权限一致。
- **[取舍] 选择模式中语言、动画只在预览里生效。** 用户看不到「整个界面换成英文」的效果，但避免了在候选之间切换时整页抖动；确认后立即全局生效。

## Migration Plan

- 配置新增 `bubble_width`（60/70/80）、`density`（`comfortable`/`compact`）、`time_format`（`24h`/`12h`），全部 `omitempty`；缺省或非法值按默认处理，旧配置无需迁移，降级到旧版本时这些字段被忽略。
- 回滚：本变更不涉及服务端与协议，回滚客户端即可。
