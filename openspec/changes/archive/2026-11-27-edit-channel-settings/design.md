# Design

## Context

现有频道具备公开和私有属性，客户端按加入关系显示频道或推荐项。编辑需要更新现有频道，同时保持这些权限边界。

## Goals / Non-Goals

**Goals**

- 使表单中的选项无需提交即可确认，且清楚标出创建、保存和取消动作。
- 让创建者能编辑既有频道属性，继续使用原频道和历史消息。
- 公私切换后及时更新在线用户的列表。

**Non-Goals**

- 此变更的范围限于频道属性编辑和发现。

## Decisions

1. 复用频道表单。编辑时预填属性，名称和简介同宽，简介根据终端高度扩展。公开开关通过位置与颜色体现状态。
2. 服务端根据频道创建者 ID 授权，在同一条数据库更新中保存属性和名称索引。加入、退出和编辑按服务端顺序处理，使加入校验使用当前可见性。
3. 可见性变化按受众发布目录事件，事件携带频道 ID。客户端处理移除事件时使较早的列表响应失效，避免私有频道重新出现在推荐中。
4. 握手响应声明是否支持编辑。旧服务端拒绝编辑时，保留草稿并显示更新重启提示。

## Risks / Trade-offs

- 公开转私有保留现有成员，因此编辑可见性不会中断已加入用户。
- 极矮窗口使用紧凑布局，输入框随可用高度收缩。
