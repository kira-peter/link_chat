# Design

## Context

三个问题的现状（见 `proposal.md`）：

- 客户端令牌存在全局配置文件里，同机多开必然共用身份。
- 服务端 `readLoop` 用 `context.WithTimeout(heartbeat*2)` 包住每次 `Read`，而客户端从不主动发帧。WebSocket Ping 是控制帧，不会被当作应用帧统计，所以静默 60 秒即被判死。
- 规格当前允许多端在线（`openspec/specs/account-auth/spec.md` 的「同一用户多端登录」场景），没有顶号机制。

## Goals / Non-Goals

**Goals:**

- 同一台机器能同时登录不同账号，零额外配置。
- 空闲连接稳定存活，断线只在真正失联时发生。
- 后登录顶掉先登录，且被顶掉的一方知道自己为什么下线、从哪登录。

**Non-Goals:**

- 不做「允许多端并存」的开关。单会话是产品决定，不做成可选。
- 不做真正的 GeoIP 查询（需要额外的库和数据文件，且离线环境不可用）。地点用来源地址表示，服务端在配置了 `geoip_db` 时才补地理信息。
- 不做设备指纹或推送通知。

## Decisions

### 1. 实例名进配置路径，而不是进令牌

**选择**：`-as <name>` 决定配置文件路径 `instances/<name>.json`；未指定时用 `default`。

**理由**：问题在于"两个进程共享一份凭据"，最小且正确的修法是让凭据文件按实例分开。把实例名塞进令牌会让服务端难以区分"同一实例重连"与"同一实例重开"，反而复杂。

**替代方案**：
- *令牌存在项目目录*：污染仓库，且 `git status` 噪声。
- *环境变量选目录*：可用但不如 `-as` 直观；两者都支持成本很低，但先把主路径做干净。

**兼容**：老路径 `%APPDATA%/link-chat/config.json` 若存在且 `instances/default.json` 不存在，首次启动时迁移过来，用户不会被迫重新登录。

### 2. 心跳用应用层请求，而不是依赖 WebSocket Ping

**选择**：客户端每 `heartbeat_interval/2` 发一个 `presence.ping` 请求，服务端回 `pong`。服务端保留原有的 Ping 控制帧（防中间设备掐连接），但**读超时只由应用帧重置**。

**理由**：`coder/websocket` 的 `Read` 返回应用消息；控制帧在库内部处理，不会让 `Read` 返回。所以要让读超时有意义，客户端必须发应用帧。这正好也是规格里写的行为。

**替代方案**：
- *把读超时去掉*：连接死了也发现不了，不可接受。
- *服务端放宽到 5 倍心跳*：只是把问题推后，仍会误杀。

**注意**：心跳请求与普通请求共享同一 `id` 序列与限流预算。按默认 30 秒心跳，每 15 秒一个请求，远低于 20 req/s 上限。

### 3. 顶号在登录路径上完成，不引入会话表

**选择**：登录/注册成功、签发新令牌之前，先 `DeleteSessionTokensForUser(userID)`，并通过 Hub 找到该用户的所有连接、推 `session.replaced` 后关闭。

**理由**：令牌已经是唯一凭据，吊销它就等于使旧会话失效；Hub 已经知道每条连接属于谁。不需要额外的「会话注册表」——那会变成第二份需要保持一致的状态。

**替代方案**：
- *维护 sessionID → conn 映射*：更精确（可以只踢同一设备重连），但引入一份与令牌重复的状态。

**关键点**：必须先推事件再关连接。`Conn.enqueue` 在队列满时会直接关连接，所以顶号时用同步写入（`writeThenClose`），确保通知一定送达。

### 4. 地点信息：地址为主，地理为辅

**选择**：`location` 字段直接承载来源地址字符串（如 `192.168.1.23:51234` 或经代理解析出的客户端 IP）。若配置了 `geoip_db` 且能解析，则拼成 `上海, CN (203.0.113.7)`。

**理由**：不依赖外部服务，离线可用，且"从哪台机器登录"这个问题用 IP 已经能回答。GeoIP 是可选增强。

**隐私**：地址只展示给账号本人（被顶掉的那一方），不进日志正文。
