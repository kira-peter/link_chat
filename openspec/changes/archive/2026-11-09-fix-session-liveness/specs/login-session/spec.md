# Spec Delta

## Purpose

定义单会话登录：同一账号在任意时刻只有一个有效会话，后到者顶掉先到者，被顶掉的一端收到明确提示并停止自动重连。这让「谁在用这个账号」始终可回答，也让异常登录无法悄悄共存。

## ADDED Requirements

### Requirement: 单会话约束

同一账号 MUST 在任意时刻只有一个有效会话。任何建立新会话的途径——包括用已保存令牌自动恢复——MUST 吊销该账号此前的会话并终止其连接。

#### Scenario: 第二处登录顶掉第一处
- **WHEN** 账号 `alice` 已在一处登录，又在另一处成功认证
- **THEN** 系统吊销第一处的会话令牌并关闭其连接，第二处的会话正常建立

#### Scenario: 自动恢复也算建立会话
- **WHEN** 一个客户端用已保存的令牌自动恢复会话，而该账号已有其他活跃会话
- **THEN** 已有会话被吊销并被通知，与一次显式登录完全相同

#### Scenario: 恢复时轮换令牌
- **WHEN** 客户端用已保存的令牌恢复会话
- **THEN** 系统签发一个新令牌并作废被出示的令牌，使被顶掉的一端无法用旧令牌反顶回来

#### Scenario: 共用同一凭据的两个客户端
- **WHEN** 两个客户端因共用凭据文件而持有同一个令牌，后启动的那一个恢复会话
- **THEN** 最终只有一处会话存活，先启动的一方收到顶号通知

#### Scenario: 顶号不影响其他账号
- **WHEN** 账号 `alice` 在新位置登录
- **THEN** 账号 `bob` 的会话完全不受影响

#### Scenario: 顶号不影响找回密码令牌
- **WHEN** 账号正在找回密码流程中且持有重置令牌，此时该账号在别处登录
- **THEN** 重置令牌仍然有效，找回流程不受打断

#### Scenario: 同一连接重复认证
- **WHEN** 已认证的连接再次提交登录且认证成功
- **THEN** 系统不把自己判定为被顶掉的一方，会话保持

### Requirement: 被顶掉的提示

被顶掉的连接 MUST 在关闭前收到一个 `session.replaced` 事件，其中 MUST 包含顶号方登录的地点信息。

#### Scenario: 收到包含地点的通知
- **WHEN** 会话被另一处登录顶掉
- **THEN** 被顶掉的连接收到 `session.replaced` 事件，包含账号名、来源地址、时间与（可选）设备名

#### Scenario: 通知先于断开
- **WHEN** 服务端决定顶掉某条连接
- **THEN** 该事件在连接关闭之前送达，客户端不因竞态错过它

#### Scenario: 地点不可解析时仍给出地址
- **WHEN** 无法获得地理位置信息
- **THEN** 事件中仍包含原始来源地址，不因缺少地理信息而省略整个地点字段

### Requirement: 被顶掉一端的后续行为

被顶掉的客户端 MUST NOT 自动重连，MUST 清除本地保存的令牌，并 MUST 向用户展示账号已在别处登录及其地点。

#### Scenario: 不进入重连循环
- **WHEN** 客户端收到 `session.replaced`
- **THEN** 客户端停止重连，不显示重连倒计时

#### Scenario: 清除本地令牌
- **WHEN** 客户端收到 `session.replaced`
- **THEN** 本地配置中的令牌被删除，下次启动不会尝试用它恢复会话

#### Scenario: 展示提示界面
- **WHEN** 客户端收到 `session.replaced`
- **THEN** 界面显示「账号已在别处登录」以及地点与时间，并提供重新登录的入口

#### Scenario: 用户选择重新登录
- **WHEN** 用户在提示界面选择重新登录并成功认证
- **THEN** 该账号在另一端被顶掉，流程对称
