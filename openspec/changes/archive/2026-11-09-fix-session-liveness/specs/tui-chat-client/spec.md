# Spec Delta

## MODIFIED Requirements

### Requirement: 登录与首启引导

客户端 SHALL 用一个自足的登录面板完成身份认证，并在失败时给出可操作的说明。服务器地址 MUST 来自客户端配置而非常驻的输入字段，默认指向本机。每个客户端实例 MUST 使用独立的凭据存储。

#### Scenario: 首次启动
- **WHEN** 客户端没有任何有效配置
- **THEN** 客户端打开登录面板，只要求用户名与密码，服务器地址取配置中的默认值

#### Scenario: 服务器地址来自配置
- **WHEN** 用户需要连接另一台服务器
- **THEN** 用户修改配置文件或用启动参数指定地址，登录面板本身不提供该字段

#### Scenario: 服务器不可达
- **WHEN** 配置中的服务器地址无法建立连接
- **THEN** 登录面板显示不可达提示与正在使用的地址，并保留已填的用户名供重试

#### Scenario: 登录失败
- **WHEN** 用户提交错误凭据
- **THEN** 客户端在面板内显示失败原因（凭据错误、被限流等），不清空用户名

#### Scenario: 令牌持久化
- **WHEN** 用户登录成功并退出客户端后再次启动
- **THEN** 客户端使用已保存的令牌直接进入主界面，无需重新输入密码

#### Scenario: 同机多实例互不干扰
- **WHEN** 同一台机器上以不同实例名启动两个客户端
- **THEN** 二者使用各自的凭据文件，可以登录不同账号，互不覆盖

#### Scenario: 默认实例
- **WHEN** 用户未指定实例名启动客户端
- **THEN** 客户端使用名为 `default` 的实例配置，多个未命名的客户端共享该实例

## ADDED Requirements

### Requirement: 会话被顶掉时的界面

客户端收到 `session.replaced` MUST 停止重连、清除本地令牌，并展示账号已在别处登录的提示，包含地点与时间。提示 MUST 提供重新登录入口。

#### Scenario: 显示顶号提示
- **WHEN** 客户端收到 `session.replaced`
- **THEN** 界面显示提示对话框，内容包含账号名、地点与时间，以及重新登录的指引

#### Scenario: 清除本地凭据
- **WHEN** 客户端收到 `session.replaced`
- **THEN** 本地配置文件中的令牌被删除，下次启动不会尝试用它恢复

#### Scenario: 不进入重连
- **WHEN** 客户端因顶号而断开
- **THEN** 状态栏不显示重连倒计时，客户端停留在提示界面

#### Scenario: 重新登录
- **WHEN** 用户在提示界面确认并完成认证
- **THEN** 客户端正常进入主界面，此前顶掉本端的会话被反过来的同一机制顶掉
