# Design

## Context

现有认证只有注册与登录两条路径（见 `openspec/specs/account-auth/spec.md`）。登录面板把服务器地址当成一个可编辑字段，表单里三个输入项挤在一起，提示文本放不下。

约束：

- 客户端是终端程序，鼠标支持是**可选**能力（tcell 需显式开启，且不是所有终端都提供）。链接必须首先是键盘可达的，点击是增强而非前提。
- 服务端存储是 JSON 文件，`Storage` 接口已定型。新增字段要能读回老数据（`encoding/json` 对缺失字段填零值，天然向后兼容）。
- 已有账号没有安全问题，必须能继续登录。

## Goals / Non-Goals

**Goals:**

- 登录面板自足：两个字段、一个按钮、两条链接，键盘与鼠标都可用。
- 找回密码在不依赖邮件的前提下成立——安全问题是这个规模的自建服务能实际交付的唯一方案。
- 重置令牌走最短路径：一次性、短期、只用于改密码。

**Non-Goals:**

- 不做邮箱/短信找回。需要 SMTP 配置与验证流程，与"单二进制可公网部署"的定位冲突。
- 不做多因素认证。
- 不迁移老账号：没有安全问题的账号不能用找回，这是可接受的，因为数据目录在本机、管理员可以直接改文件或重建账号。

## Decisions

### 1. 重置令牌复用 `tokens` 集合，加 `Purpose` 字段

**选择**：`storage.Token` 增加 `Purpose`（`"session"` / `"reset"`），默认空值视为 `session`。

**理由**：重置令牌与会话令牌的生命周期、吊销语义高度相似（都是 opaque、都存哈希、都带过期）。新开一套集合意味着多一份持久化代码、多一条加载路径、多一处可能写坏的地方。加一个字段即可，且零值兼容老数据。

**替代方案**：
- *独立的 `resets.json`*：更清晰的语义边界，但复制了 90% 的代码。
- *令牌自带前缀区分*：`reset_` 前缀，靠字符串判断。可行但脆弱——校验逻辑散落在字符串解析里。

**关键点**：重置令牌的有效期与 TTL 不同（5 分钟 vs 30 天），因此 `Token` 的过期时间字段必须按用途解释，`userForToken` 只接受 `Purpose == session` 的令牌。

### 2. 安全答案归一化后再哈希

**选择**：答案转小写、去掉首尾空白与内部连续空白、再走同一个 Argon2id。

**理由**：安全问题是人手输入的回忆题。"Blue Harbor" 和 "blue  harbor" 是同一个答案，要求用户记住自己当时怎么敲的空白是错误的。归一化必须在**哈希前**做，因为哈希不可逆。

**替代方案**：
- *多哈希几种变体逐一比对*：组合爆炸，且增加校验耗时（每次 Argon2id 都有成本）。
- *不归一化*：用户自己在注册时看到输入，理论上可复现，但实际会造成大量找回失败。

**注意**：归一化只影响答案，不影响密码。密码不做任何变形。

### 3. 三步找回拆成三个独立请求，而不是一次提交

**选择**：`auth.recover.question` → `auth.recover.verify` → `auth.recover.reset`，中间用一个短期令牌串联。

**理由**：安全问题需要在第二步才展示给用户——第一步只是用户名。若做成一次提交，客户端必须猜测问题是什么，或者服务端把问题塞进错误响应里，两者都不干净。拆成三步后每一步的失败都有准确语义：用户名不可找回 / 答案错误 / 令牌过期。

**替代方案**：
- *一次提交（用户名+答案+新密码）*：客户端无法在回答前展示问题。
- *两步（校验答案后直接在同一次请求里带新密码）*：可行，但把"回答"和"决定新密码"耦合在一个请求里，用户在第二步失败就得重填密码。

### 4. 用户名枚举：统一为 `cannot_recover`

`auth.recover.question` 对"用户不存在"与"账号无安全问题"返回完全相同的错误码与文案。否则这个接口就变成了账号枚举工具，抵消了登录路径上已有的防护（登录失败不区分账号是否存在）。

**代价**：真实用户看到"无法找回"时不知道是自己记错了用户名还是账号有问题。用文案兜住："该账号无法找回，请确认用户名，或联系管理员。"

### 5. 链接用 hover 区判定点击，而不是解析 ANSI

**选择**：`LoginModel` 记录每个链接占据的屏幕行范围；鼠标事件到达时，用行号判定落在哪条链接上。

**理由**：tcell 的鼠标事件给的是单元格坐标，而我们的渲染本来就是按行组织的。行级判定简单、稳定，不需要维护字符级命中区。

**键盘优先**：焦点模型（`FocusArea`）是主路径——Tab 循环、Enter 激活。鼠标只是在这之上加一层。终端不报鼠标事件时，功能完全不受影响。

### 6. 服务器地址从表单移出，但保留可达的覆盖手段

默认 `ws://127.0.0.1:8100/ws`，写进配置文件。改地址的三条路径按优先级：

1. `-server` 启动参数
2. 配置文件 `server` 字段
3. 内置默认值

登录面板不再提供该字段，但会在连接失败时**显示正在使用的地址**，这样用户能判断是地址错了还是服务没起来。

## Risks / Trade-offs

- **安全问题强度有限** → 它是"知道即可重置"的凭据。缓解：答案同样 Argon2id 哈希存储、错误答案计入退避限流、重置后吊销全部会话。文档中明确它的安全边界。
- **用户忘记安全答案** → 无法自助找回。缓解：注册表单明确提示"请记住这个答案"；管理员可直接编辑 `users.json` 或用数据目录重建账号。
- **老账号无法找回** → 已在规格中明确，返回 `cannot_recover`。
- **重置令牌在 5 分钟内可被重放** → 一次使用后立即删除，缩短窗口。实际上攻击者需要先答对安全问题才能拿到令牌，风险与答案泄露同级。
- **鼠标支持在部分终端不可用** → 键盘是主路径，功能零损失。

## Migration Plan

1. 协议：新增操作与错误码，`RegisterReq` 加两个可选字段。
2. 存储：`User` 与 `Token` 加字段；老文件缺字段时为零值，无需迁移脚本。
3. 服务端：新增三个处理器 + 注册校验。
4. 客户端：登录面板重构、注册表单、找回向导、鼠标事件。
5. 文档：`docs/client.md` 补注册与找回说明，明确安全问题的边界。

**回滚**：新增字段对旧版本是未知字段，`encoding/json` 解析时忽略，因此降级回旧二进制不会损坏数据（安全问题会丢失，但登录与消息不受影响）。
