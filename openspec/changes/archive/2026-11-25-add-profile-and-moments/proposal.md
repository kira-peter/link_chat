# Proposal

## Why

link_chat 现在只有"按用户名打开私聊"和公开频道，人与人之间没有持续的关系，也没有地方展示自己或分享日常。主页让每个人有一个可被认识的身份（昵称、签名、头像），朋友圈让熟人之间有聊天之外的轻量互动。这两者都依赖"谁是谁的朋友"，所以本变更同时引入双向好友关系。

## What Changes

- **好友关系**（新能力 `friends`）：按用户名发好友申请并附言；对方同意或拒绝；在线时实时到达、离线时上线后可见；好友列表与删除好友；拉黑——被拉黑者不能再申请、看不到拉黑者的主页与动态，已有好友关系随之解除。
- **个人主页**（新能力 `user-profile`）：昵称（可改，与唯一的用户名分开）、一行个性签名、用"一个字符或 emoji + 一种颜色"代替的头像；主页显示昵称、用户名、签名、头像、注册时间与此人最近的动态；在自己的主页上直接编辑；从主页一键发私聊。头像也出现在会话列表与消息气泡上。
- **朋友圈**（新能力 `moments`）：发纯文本动态（字数上限）；可见范围"所有好友 / 仅自己"；时间线是自己与好友的动态，按时间倒序分页；点赞与取消、显示点赞的人；评论与回复某条评论，评论与点赞只对作者及作者与评论者的共同好友可见；删除自己的动态与评论，动态作者可删除自己动态下的任何评论；新动态的未读红点与"有人赞了/评论了你"的通知。
- **客户端界面**（修改 `tui-chat-client`）：左侧底部入口新增"朋友圈"（与设置、帮助、关于并列，排在最前），打开后是右侧页面；页顶是好友申请与互动通知区；新增"主页"页面；会话列表与气泡显示头像。
- **协议**（修改 `chat-protocol`）：新增好友、主页、动态相关的请求、事件与错误码。
- **管理后台**（修改 `admin-console`）：新增"动态"区域（需要 `chat.view` 查看、`users.moderate` 删除），可查看、删除任意动态与评论。
- **处分与审计**（修改 `account-moderation`）：禁言期间不能发动态、不能评论，也不能修改主页资料；后台删除动态和评论写入审计日志。
- 发动态、评论、点赞、好友申请均受按账号的频率限制。

## Capabilities

### New Capabilities
- `friends`: 双向好友关系的建立、解除与拉黑，以及由此决定的"谁能看到谁"。
- `user-profile`: 每个账号的昵称、签名、头像，以及主页的查看与编辑。
- `moments`: 朋友圈动态的发布、可见范围、时间线、点赞、评论与通知。

### Modified Capabilities
- `tui-chat-client`: 左侧底部入口新增"朋友圈"；新增主页与朋友圈页面；会话列表与消息显示头像。
- `chat-protocol`: 新增好友、主页、动态的请求、事件与错误码。
- `admin-console`: 新增"动态"区域；区域与权限对应关系增加一项。
- `account-moderation`: 禁言范围扩大到动态、评论与主页资料；审计日志增加删除动态与评论。

## Version

Major：`3.0.0` → `4.0.0`。本变更新增了 `friends`、`user-profile`、`moments` 三项能力。

## Impact

- `pkg/storage`：新增好友、申请、拉黑、主页、动态、点赞、评论、通知的表与 `Storage` 方法。
- `pkg/protocol`：新增请求/事件/错误码与载荷类型。
- `pkg/server`：新增处理器、可见性判断、频率限制；后台新增动态区域接口与页面。
- `pkg/client`、`pkg/app`、`pkg/tui/views`、`pkg/i18n`：新增朋友圈与主页页面、底部入口、头像渲染、通知红点。
- 协议向后兼容：旧客户端不认识新事件会忽略；新客户端连旧服务端时，新请求返回 `invalid_argument`，朋友圈入口显示"服务器不支持"。
