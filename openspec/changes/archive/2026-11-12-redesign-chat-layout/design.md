# Design

## Context

动机与范围见 `proposal.md`，行为契约见两份 spec delta。本文只讲怎么做。

现状里几个直接约束方案的事实：

- 视图是纯函数：`views.*` 拿状态画单元格，不持有任何动画状态。时间由 `app` 传进来（`Elapsed`、`Depth`）。新增的折叠、飞行、光效都必须保持这一点。
- 动画预算集中在 `needsFrames` 一处：静止时零刷新。现有的 `anim.Slide` 是一个可中途改向的缓动，焦点标记已在用。
- 布局只有一个来源：`SidebarRect` / `MainRect` 由 `layout.SidebarWidth` 决定侧栏宽度，焦点标记的位置也由它们推出（`regionX`）。目前侧栏宽度只依赖窗口宽度，没有"折叠"这个自由度。
- `ActiveID` 既表示"打开了哪个会话"，登录后 `onAuthenticated` 会自动打开第一个。列表选中项 `ui.Selected` 是另一个独立的游标。
- 消息渲染目前输出 `[]renderedLine{text, style}`，一行一个字符串。边框与左右分栏需要按单元格着色，字符串模型装不下。
- 列表只有一个数据源 `VisibleConversations()`，按 `LastMessageAt` 全局排序，不区分私聊与群聊。

## Goals / Non-Goals

**Goals:**

- 折叠、展开、名字飞行由**一个**随时间推进的进度值驱动，三者永远同步，中途改向不会错位。
- 气泡布局是纯函数：给定消息、宽度、当前用户，输出确定的矩形与文字，可以脱离终端做快照测试。
- 表单输入框的"铺满宽度"只写在一处，登录、注册、找回密码共用。
- 登录后初始状态、折叠状态、焦点状态之间的关系用一个小的状态机说清楚，不靠散落的 if。

**Non-Goals:**

- 不改协议与服务端。私聊与群聊的区分用现有的 `Kind` 字段，底部入口不是会话，不进协议。
- 不做可拖拽的列表宽度，不做列表的"窄条"收起形态（已与你确认：完全收起）。
- 不做消息的点击、回复、选中；气泡只是渲染。
- 不改登录与重连的认证流程，只改它们的呈现。

## Decisions

### 1. 折叠进度是一个 0–1 的值，布局从它推出

新增 `anim.Slide` 的一个实例 `a.anim.fold`，值域 0（列表展开）到 1（完全折叠）。`app` 在每帧读取 `fold.At(now)`，传给视图。

布局函数改为 `Layout(content, fold float64)`：侧栏宽度 = `SidebarWidth(w) * (1 - fold)`，聊天区拿走剩余。名字飞行的位置也由同一个 `fold` 插值得到：起点是该行在列表里的坐标，终点是聊天区标题的坐标，`pos = lerp(from, to, fold)`。

这样折叠、聊天区扩展、名字飞行是**同一个数的三个读法**，不存在"三个动画各走各的、结束时对不齐"。中途改向时 `Slide.MoveTo` 本来就从当前值出发，三者一起转向。

**备选：** 给每件事一个独立动画。否决：要手工保证三者时序一致，中途改向时三个起点各自要重算，最容易出视觉错位的 bug。

**代价：** 折叠中间态时侧栏宽度是小数 × 宽度取整，窄到 `SidebarMin` 以下时列表内容会被截断得很难看。见风险 1。

### 2. "选中"与"打开"拆开，折叠状态跟着"打开"走

- `ui.Selected`：列表游标，只在列表聚焦时有意义，上下键移动。
- `st.ActiveID`：已打开的会话，决定聊天区显示什么。
- 折叠状态 `folded`（布尔，目标值）：由**焦点**决定——焦点在输入区则折叠，焦点在列表则展开。`fold` 动画只是朝这个目标走。

规则只有一条：**焦点进入输入区 ⇒ 目标折叠；焦点回到列表 ⇒ 目标展开。** 按 Enter 打开会话、按右键、按 Esc、Tab 都只是"移动焦点"的不同入口，折叠自动跟随，不需要每个入口各自处理动画。

没有打开的会话时（登录后的初始态），聊天区是欢迎页，输入区不可用，右键与 Tab 不得把焦点送去输入区，否则会折叠出一个空白的整屏。这条规则放在 `moveFocus` 里统一拦截，对应 spec 的「没有打开的会话时向右」。

**备选：** 折叠与 `ActiveID` 直接绑定（有会话就折叠）。否决：按左键展开列表时会话仍然是打开的，两者会打架。

### 3. 列表按种类分三块，用一个"行模型"统一选中

新增 `client.ListRow` 序列：`[标题行 私聊] [私聊…] [标题行 群聊] [群聊…] [入口 设置] [入口 帮助] [入口 关于]`。每一行有 `Kind`（Header / Conversation / Entry）与可选的目标。`ui.Selected` 变成这个序列里的**可选行**下标，标题行不可选，上下键跳过。

这样跨分区移动、移到底部入口、选中光效都落在同一套"行"上，渲染与按键处理不需要知道有几块。底部入口固定在列表区最下方，列表本身在中间区域滚动；入口不随滚动移动。

私聊与群聊各自按 `LastMessageAt` 排序，沿用现有的比较函数，只是先按 `Kind` 分组。过滤作用于两块，入口行不参与过滤。

**备选：** 三块各自维护一个游标，用一个"当前块"变量切换。否决：边界处的上下键要手写三套跳转，且选中光效要在三处各画一遍。

### 4. 选中光效复用 `Shimmer`，参数独立

新增 `anim.ListShimmer`（比 `ButtonShimmer` 更窄更慢，因为列表行更长、一屏同时只有一行在亮）。选中行的整行背景保持不变，只有文字的**前景色**随 `Brightness` 混合，这与登录按钮光带的做法一致，并由 spec 的「光带不改变背景范围」约束。

`needsFrames` 增加一项：列表聚焦、有选中行、动画开、折叠完全展开时为真。折叠过渡中不跑光带（避免两种动画叠加，且那时列表正在变窄）。

### 5. 消息渲染从字符串改为"气泡"，布局与绘制分开

`buildLines` 目前产出带单一样式的字符串，装不下边框与左右分栏。改为两步：

1. **布局**（纯函数）：`LayoutMessages(msgs, width, userID, now) []Item`。`Item` 是以下之一：气泡（侧、矩形、折行后的文字、边框令牌、是否显示名字）、时间行（居中文字）、系统行、空行。每个 `Item` 有确定的高度。
2. **绘制**：按滚动窗口逐个 `Item` 画单元格。

滚动仍然以"行"为单位，因为每个 `Item` 的高度是整数行，总高度是各 `Item` 高度之和，`Render` 返回的 `total` 含义不变，`app` 里钳制滚动的代码不动。

气泡宽度 = `min(最长折行 + 边框与内边距, 消息区宽度的 70%)`，在气泡内按显示宽度折行（沿用 `layout.Wrap`，CJK 与 emoji 的宽度仍只来自 `layout.StringWidth`）。靠左的气泡 x = 0，靠右的 x = 区宽 − 气泡宽。

合并规则沿用：同一人两分钟内的连续消息同侧相邻，只有一组的第一条带名字。他人的名字放在气泡**上方**一行（不占气泡内空间，宽度计算更简单）；自己的不显示名字。

**备选：** 在现有字符串模型上用字符画边框。否决：边框颜色要逐段不同，且右对齐需要知道每行的实际宽度，字符串上拼接会让折行与着色相互纠缠。

### 6. 时间只是一个居中的 `Item`

时间行的触发条件沿用现有逻辑（首条、间隔超过 5 分钟）。渲染成一行居中文字，上下各 1 个空行，没有横线字符。无 Unicode 与否对它没有影响。

### 7. 气泡边框色是两个新的主题令牌

在 `Palette` 里加 `BubbleSelf`、`BubbleOther`。`ink` 与 `paper` 各定一组，要求两色互不相同且都与消息区背景有对比。`quantize256` 之后仍是两种颜色；`monochrome` 里两者映射到不同的灰度，并配合不同的线型（实线 `─│` 对虚线 `┄┆`）保证单色下仍可区分，对应 spec 的「单色终端仍可区分双方」。

视图只通过令牌取色，不出现颜色常量，符合「语义化色彩令牌」。

### 8. 输入框：一个函数管三处，铺满靠"先填满再写字"

现在的 `fieldBox` 在聚焦时用 `TextFill` 铺背景，未聚焦时只写文字、没有背景，这就是"只有字那一块是深色"的来源。改为：**无论聚焦与否，先把整个输入宽度用输入背景令牌填满，再把文字写上去。** 聚焦与未聚焦用不同的背景令牌。

新增两个令牌 `Input`、`InputFocus`（见 spec「输入框外观令牌」）。登录、注册、找回密码、频道名提示都走这个函数，一处改，处处生效。

密码行的占位圆点：已记住状态下 `fieldBox` 被传入一个固定长度（如 8 个）的圆点串，而不是真实密码；焦点在该行时不画光标。圆点个数是一个常量，与任何真实密码无关。

### 9. 登录面板：错误信息位置与链接行的左右键

**错误位置：** 错误占用密码行与按钮之间的那一行，**始终预留**（没有错误时是空行），所以面板高度不变。居中靠 `(rowW - width) / 2`，宽度超出就截断。"正在连接"与服务器地址仍在底部状态行。因为预留了一行，`loginPanelHeight` 增加 1。

**左右键：** `LoginFocus` 的循环顺序是 用户名 → 密码 → 按钮 → 忘记 → 注册，目前左右键在面板里完全不被处理。只给两个链接加上"左右切换"：焦点在 `Forgot` 时按右键到 `Register`，反之亦然，边界处为空操作；其它焦点上左右键行为不变（字段里仍是光标）。上下键与 Tab 的行为保持原样，对应 spec 的「上下键仍可移动焦点」。

### 10. 登录后初始态

`onAuthenticated` 里去掉自动打开第一个会话。登录成功后：`ActiveID = ""`，`Focus = FocusList`，`fold` 目标为展开，选中第一个可选行。聊天区显示现有的欢迎页（已有 `renderWelcome`）。重连后若 `ActiveID` 已有值则沿用，不受影响。

## Risks / Trade-offs

- **风险 1：折叠中间态列表被压得太窄，内容难看。** → 折叠进度超过一个阈值（例如 0.6）后不再绘制列表内容，只让空白收缩；名字飞行此时已经离开列表，视觉上列表是"被抽走"而不是"被挤扁"。快照测试覆盖 0、0.3、0.6、1 四个进度。
- **风险 2：名字飞行的起点坐标依赖列表当前滚动位置。** 列表滚动后该行可能不在可见区。 → 起点钳制到列表可见区的边缘，名字从边缘飞出，不会飞出屏幕外。
- **风险 3：气泡让同一屏能显示的消息变少**（每条多出上下边框两行，合并组还要留名字行）。 → 这是你要的设计，但要在窄终端上验证。极窄时（消息区小于一个阈值）退化为不带边框的左右分栏，边框是可降级的装饰。
- **风险 4：`buildLines` 重写会触及消息渲染的全部既有测试**，包括折行对齐、CJK、已删除占位、合并窗口。 → 先写布局纯函数的测试再改绘制，原有断言按新规格逐条迁移，不是删掉。
- **风险 5：登录后不再自动打开会话，改变了老用户的肌肉记忆**，且端到端测试里大量用例假设登录后就有 `ActiveID`。 → 测试辅助函数集中提供一个"登录并打开某会话"的入口，避免每个用例各自处理。这是 proposal 里已标注的 BREAKING。
- **风险 6：同时叠加了折叠、光带、焦点标记三种动画。** → 折叠中暂停光带；焦点标记在折叠过渡中跟着 `fold` 走，不再另起一个 `slide`（见下方 Open Questions）。预算仍然只在 `needsFrames` 一处判定。
- **风险 7：本变更改的登录需求与 `refine-login-panel` 重叠。** → 本变更的 delta 以后者归档后的 spec 为基线，必须在其归档之后再应用；`openspec validate` 目前对此给出 INFO，归档后会消失。

## Open Questions

- 焦点标记（`▌`）在新布局里的去向：折叠时列表不可见，它是留在聊天区标题处不动，还是随名字一起飞？倾向前者（标记只表示"键盘在聊天区"），对 spec 没有影响，实现时再定。**已定**：标记不飞，静止时紧贴在聊天区标题左边一格；标题居中，所以折叠后它在屏幕正上方中央，标题文字变化（成员数到达）导致标题重新居中时，静止的标记也跟着重新定位。
- 「关于」对话框里版本号的来源：目前代码里没有版本常量。倾向用 `-ldflags` 注入、缺省显示 `dev`，不影响 spec。
