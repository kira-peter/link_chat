# Proposal

## Why

服务端现在无法知道谁在用哪个版本的客户端。版本号只能靠构建时手动传入，忘了传就显示 `dev`，所以关于页的版本也不可靠。即将上线的管理后台要展示每个用户的客户端版本，服务器还要能拒绝过旧的客户端，这些都需要一个可靠、统一的版本号。

## What Changes

- **版本规则**：每个变更按改了什么来升一次版本号。
  - 新增能力的大提案：`x+1`，`y` 和 `z` 归零。
  - 只修改已有能力的小提案：`y+1`，`z` 归零。
  - 不改任何规格的修复或优化：`z+1`。

  规则写进 `openspec/config.yaml`，提案和任务清单生成时会自动带上。
- **版本号来源**：仓库根目录新增 `VERSION` 文件，内容是 `x.y.z` 三段数字，初始值为 `0.0.0`，本变更完成后按版本规则升为 `1.0.0`。服务端和客户端编译时都把这个文件嵌进二进制，两者版本号永远一致。直接执行 `go build` 也能得到正确的版本，不再依赖 Makefile 传参。
- **构建校验**：`VERSION` 的格式不合法时，测试会失败，让问题在发布前暴露。
- **握手上报版本**：
  - 客户端在 `hello` 中上报自己的版本号，复用已有的 `client` 字段。
  - 服务端在 `hello-ack` 中返回自己的版本号，复用已有的 `server` 字段。
  - 两个字段的格式统一为 `<名称>/<x.y.z>`。
  - 协议版本号 `version: 1` 保持不变，它和发布版本号是两回事。
- **最低客户端版本**：服务端新增配置 `min_client_version`，默认为空，表示不限制。
  - 客户端版本低于这个值，或者没有上报合法的版本号，握手时就会被拒绝，返回新错误码 `client_outdated`，响应中带上最低版本。
  - 客户端收到后停止自动重连，并提示「客户端 x.y.z 过旧，请升级到 a.b.c」。
- **记录版本**：
  - 服务端把客户端版本记在连接上。
  - 签发会话令牌时，同时记录客户端版本。
  - 登录、恢复会话、顶号相关的日志里会带上版本号。
  - 后台接入后可以直接读取这些信息。
- **显示版本**：
  - 服务端启动时在日志里打印自己的版本。
  - 服务端和客户端都支持 `-version` 参数，打印版本后退出。
  - 客户端的关于页继续显示版本，数据来源改为 `VERSION` 文件。
- **移除旧的注入方式**：Makefile 的 `VERSION=` 注入和 `pkg/app.Version` 变量被移除，版本统一由新的包 `pkg/version` 提供。

## Version

Major：`0.0.0` → `1.0.0`。本变更新增了 `build-version` 能力。

## Capabilities

### New Capabilities
- `build-version`：发布版本号的格式、唯一来源、比较规则，以及服务端和客户端如何暴露版本号（`-version` 参数、启动日志、关于页）。

### Modified Capabilities
- `chat-protocol`：握手时双方交换发布版本号；新增 `client_outdated` 错误码。
- `server-runtime`：新增配置项 `min_client_version`；启动日志打印版本；运行日志带上客户端版本。
- `tui-chat-client`：客户端版本过旧时的提示，以及停止重连的行为。

## Impact

- **新增**：
  - `VERSION` 文件。
  - `pkg/version` 包，负责嵌入版本、解析和比较。
- **协议（`pkg/protocol`）**：
  - 新增错误码 `client_outdated`。
  - `client` 和 `server` 字段的取值格式有了约定。
  - 帧结构不变。
- **服务端（`pkg/server`、`pkg/storage`）**：
  - 握手时检查客户端版本。
  - 连接和令牌记录客户端版本，`Token` 新增字段 `client_version`，可以省略。
  - 新增配置项 `min_client_version` 和对应的环境变量。
- **客户端（`pkg/client`、`pkg/app`、`pkg/i18n`）**：
  - 握手时上报版本。
  - 处理 `client_outdated`。
  - 关于页的版本来源改为 `pkg/version`。
- **构建**：
  - Makefile 删除 `VERSION` 注入。
  - README 说明发版流程：修改 `VERSION`，然后提交。
- **兼容性**：
  - 新服务端未配置 `min_client_version` 时，旧客户端照常连接，后台显示它的版本为「未知」。
  - 配置了 `min_client_version` 之后，旧客户端会被拒绝。旧客户端不认识 `client_outdated`，会把它当作一般的连接失败处理并按退避重试，这是可以接受的。
  - 新客户端连接旧服务端时，不受影响。
- **后续**：`add-admin-console` 在用户详情、在线列表和会话来源里显示客户端版本，并在概览中显示在线客户端的版本分布。这部分在本变更归档后，补进后台提案。
