# Spec Delta

## Purpose

定义 link_chat 的发布版本号：格式、唯一来源、比较规则，以及服务端与客户端如何对外报告自己的版本。它让运维和管理员能确定每个进程、每个连接上的客户端到底是哪一版。

## ADDED Requirements

### Requirement: 版本号格式

发布版本号 MUST 为 `x.y.z` 形式，三段均为不带前导零的十进制非负整数（`0` 本身除外），不带 `v` 前缀或任何后缀。

#### Scenario: 合法版本号
- **WHEN** 版本号为 `1.0.0`、`1.12.3`
- **THEN** 解析成功

#### Scenario: 非法版本号
- **WHEN** 版本号为 `v1.2.3`、`1.2`、`1.02.3`、`1.2.3-beta`、空串
- **THEN** 解析失败

### Requirement: 版本比较

版本号 SHALL 按主版本、次版本、修订号依次按数值比较。

#### Scenario: 按数值而非字符串比较
- **WHEN** 比较 `0.10.0` 与 `0.9.5`
- **THEN** `0.10.0` 更新

#### Scenario: 相等
- **WHEN** 比较 `1.2.3` 与 `1.2.3`
- **THEN** 两者相等

### Requirement: 唯一版本来源

服务端与客户端 MUST 使用同一个版本号，且该版本号 MUST 只来自仓库中的一处定义；任何构建方式（包括不带额外参数的直接构建）都 MUST 得到该版本号。该定义不是合法版本号时，项目的测试 MUST 失败。

#### Scenario: 直接构建
- **WHEN** 不传任何额外参数直接构建服务端与客户端
- **THEN** 两者报告的版本号相同，且等于仓库中定义的版本号

#### Scenario: 版本定义写错
- **WHEN** 仓库中的版本号被改成 `1.2`
- **THEN** 运行测试时失败并指出版本号格式不合法

### Requirement: 版本递增规则

每个合入的变更 MUST 恰好递增一次版本号，级别由变更对规格的影响决定：
- 新增至少一个能力：主版本加一，次版本与修订号归零。
- 只修改已有能力的需求：次版本加一，修订号归零。
- 不改变任何规格的缺陷修复或优化：修订号加一。

#### Scenario: 新增能力
- **WHEN** 当前版本为 `1.0.0`，一个新增了能力的变更完成
- **THEN** 版本变为 `2.0.0`

#### Scenario: 只修改已有能力
- **WHEN** 当前版本为 `2.0.0`，一个只修改已有能力需求的变更完成
- **THEN** 版本变为 `2.1.0`

#### Scenario: 缺陷修复
- **WHEN** 当前版本为 `2.1.0`，一个不改规格的缺陷修复完成
- **THEN** 版本变为 `2.1.1`

### Requirement: 报告自身版本

服务端与客户端 SHALL 支持 `-version` 参数，打印程序名与版本号后以零状态码退出，不启动服务也不进入界面。服务端启动时 MUST 在启动日志中记录自身版本号。客户端「关于」页面 MUST 显示同一版本号。

#### Scenario: 查询客户端版本
- **WHEN** 用户执行 `link-chat -version`
- **THEN** 输出形如 `link-chat 1.0.0` 并退出

#### Scenario: 服务端启动日志
- **WHEN** 服务端启动
- **THEN** 启动日志中包含其版本号
