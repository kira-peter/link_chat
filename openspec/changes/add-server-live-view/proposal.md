# Proposal

## Why

服务端跑起来后，运维只能看滚动的技术日志，看不出「此刻谁在聊、聊给谁、哪个频道热闹」。管理后台的概览是静态数字。我们想要一个能直观看到实时活动的界面：服务端的终端里有一个简洁的实况仪表盘，管理后台里有一个酷炫的 3D 实况页，两者用同一份活动数据。

## What Changes

- **新能力 `server-live`**：服务端统一产出「活动」——上线下线、登录注册、私聊与频道消息、好友申请与关系变化、动态与点赞评论、加入或新建频道、处分——供终端仪表盘与后台实况页使用。
- **终端实况仪表盘**：服务端在交互终端中运行时默认显示（`-plain` 或输出被重定向时仍为普通日志）。
  - 顶部统计栏：版本、在线人数/用户总数、今日消息数、每分钟消息数、运行时长。
  - 中部用户列表：在线在上、离线在下，各组按最近动作排序，最新的在最上面；每行显示用户名、最近动作与多久之前；放不下时底部显示「还有 N 人」。
  - 消息动画：私聊时一个小点从发送者行飞到接收者行（接收者不在屏幕上时飞到「还有 N 人」行）；频道消息时右侧浮现该频道的框，小点飞入，频道一段时间没有活动后淡出。终端里不显示消息内容。
  - 底部日志：人可读的简化日志，一条一行实时滚动，分「消息」「社交」「账号」「系统」四类，各有颜色标签。
- **后台「实况」页**：管理后台新增一页，用 three.js 3D 呈现：用户是星体、频道是星环，消息是从发送者飞向接收者或频道的流星拖尾，抵达时粒子爆散；有 `chat.view` 权限时流星带消息内容气泡，否则只有流星。侧栏显示实时统计与分类事件流。three.js 固定版本随服务端二进制内嵌，不依赖外网。
- 服务端的普通日志、后台的事件流与现有页面保持不变。

## Capabilities

### New Capabilities
- `server-live`: 服务端活动数据、终端实况仪表盘、后台 3D 实况页。

### Modified Capabilities
- `server-runtime`: 「运行日志」：交互终端中默认显示实况仪表盘，`-plain` 恢复普通日志；仪表盘中的日志行同样不含消息内容与令牌。
- `admin-console`: 「区域按权限可见」：新增「实况」区域，需要 `stats.view`；消息内容另需 `chat.view`。

## Version

Major：`5.0.0` → `6.0.0`。本变更新增了 `server-live` 能力。

## Impact

- `pkg/server`：活动的产出与订阅（复用后台事件流的分发与权限过滤），补齐好友、动态、频道等活动的产出点；后台新增「实况」页的接口。
- `pkg/server/live`（新）：终端仪表盘，基于 tcell。
- `cmd/link-chat-server`：判断是否交互终端、`-plain` 参数，仪表盘与日志的接线。
- `pkg/server/adminweb`：新增实况页（HTML/JS/CSS）与内嵌的 three.js。
- `docs/`、`CHANGELOG.md`、`VERSION`。
- 客户端与协议不变。
